# Sticky Controls Design

**Version:** v1.19.0

## Goal

When scrolling UP, the whole page scrolls normally until the header is off-screen.
The input controls (textarea + buttons + legend) then stop at the same visual top
gutter used by the main content, allowing the reading area to continue scrolling
underneath. This keeps the input area and action buttons always accessible,
especially on mobile, without pinning the header or placing controls flush against
the top edge of the viewport.

## User Interaction Flow

1. **Initial state:** Header is visible, controls appear below header in normal document flow
2. **Scroll up:** Header moves off-screen, controls travel up
3. **Stick point:** When controls reach the main content top gutter, they stick (`position: sticky`)
4. **Continue scrolling:** Reading area (token-area) scrolls underneath the stuck controls
5. **Scroll down:** Controls unstick and return to normal position, header reappears

## Implementation

### HTML Structure Changes

```html
<main>
  <!-- NEW: Stuck-state sentinel for sticky controls visual feedback -->
  <div class="controls-sticky-sentinel" aria-hidden="true"></div>

  <!-- NEW: Sticky controls wrapper -->
  <div class="controls-sticky">
    <!-- NEW: Inner scroll container so mobile overflow does not clip the apron -->
    <div class="controls-sticky-scroll">
      <div class="input-wrap">
        <textarea id="inputText">...</textarea>
        <div style="display:flex; justify-content:flex-end; gap:8px; margin-top:8px;">
          <button id="clearBtn">Clear</button>
          <button id="pasteBtn">Paste</button>
          <button id="copyUrlBtn">Share/Copy URL</button>
          <button id="exampleBtn">Example</button>
        </div>
      </div>
      <div class="status-box info hidden" id="statusBox">...</div>
      <div class="legend hidden" id="legend">
        <span class="legend-hint legend-hint-desktop">Click morphemes...</span>
        <span class="legend-hint legend-hint-mobile">Tap morphemes...</span>
        <button id="verticalBtn">Read top to bottom</button>
        <button id="dimGrammarBtn">Dim grammar</button>
      </div>
    </div>
  </div>

  <!-- Content scrolls underneath when controls stick -->
  <div id="tokenView" class="hidden">
    <!-- legend removed from here -->
    <div class="token-area" id="tokenArea">...</div>
    <div class="token-count" id="tokenCount">...</div>
  </div>

  <div class="empty-state" id="emptyState">...</div>
</main>
```

**Key changes:**

- Add `.controls-sticky-sentinel` immediately before the sticky wrapper for
  reliable stuck-state detection
- Add `.controls-sticky` wrapper around input, status box, and legend
- Add `.controls-sticky-scroll` inside the sticky wrapper for mobile internal
  scrolling without clipping the sticky wrapper's background apron
- Move `.legend` from inside `#tokenView` to the controls wrapper
- Add `id="legend"` to the legend element for JS reference
- Add `hidden` class to legend initially (matches current behavior when `#tokenView` is hidden)

### CSS Changes

```css
/* Z-index layers */
:root {
  --sticky-controls-offset: calc(22px + env(safe-area-inset-top, 0px));
  --z-controls-sticky: 10;
}

/* Stuck-state sentinel */
.controls-sticky-sentinel {
  height: 1px;
}

/* Sticky controls wrapper */
.controls-sticky {
  position: sticky;
  top: var(--sticky-controls-offset);
  z-index: var(--z-controls-sticky);
  background: var(--bg);
  padding-top: 1px;
  padding-bottom: 12px;
}

.controls-sticky-scroll {
  background: var(--bg);
}

.controls-sticky::before {
  content: '';
  position: absolute;
  top: calc(-1 * var(--sticky-controls-offset));
  left: 50%;
  width: 100vw;
  height: var(--sticky-controls-offset);
  transform: translateX(-50%);
  background: var(--bg);
  pointer-events: none;
}

/* Visual separator when stuck (shown via JS when actually stuck) */
.controls-sticky.stuck::after {
  content: '';
  position: absolute;
  bottom: 0;
  left: 24px;
  right: 24px;
  height: 1px;
  background: var(--border-subtle);
}

@media (max-width: 600px) {
  .controls-sticky-scroll {
    max-height: calc(100dvh - var(--sticky-controls-offset));
    overflow-y: auto;
  }
}
```

**Notes:**

- Keep existing margins on `.input-wrap` (10px) and `.status-box` (14px) — don't remove them
- `background: var(--bg)` occludes scrolling content behind the sticky area
- `--z-controls-sticky: 10` places controls above content (0) but below panel (100)
- The header must remain in normal flow; it is not sticky
- `--sticky-controls-offset` matches `main`'s top padding (`22px`) plus any mobile safe-area inset
- The controls stick at that offset instead of flush against the viewport top
- `.controls-sticky::before` paints a full-width background apron above the controls so scrolling content does not show through the top gutter
- Keep overflow visible on `.controls-sticky`; otherwise mobile internal
  scrolling clips the apron and lets reading content show through the top gutter
- Mobile gets a max height and internal scroll on `.controls-sticky-scroll` so
  resized textareas or visible status messages can't consume the whole viewport
- The bottom separator only appears when `.stuck` class is added (via IntersectionObserver sentinel JS)
- Do not add a stuck-state box shadow; the final design intentionally avoids shaded halos around the controls
- This gives users feedback that controls are now in sticky state

### JavaScript Changes

Add IntersectionObserver with a sentinel to detect when controls are actually stuck:

```javascript
// ── Sticky controls visual feedback ───────────────────────────────────────────────
const controlsStickySentinel = document.querySelector('.controls-sticky-sentinel');
const controlsSticky = document.querySelector('.controls-sticky');
if (controlsStickySentinel && controlsSticky && 'IntersectionObserver' in window) {
  const observer = new IntersectionObserver(
    ([entry]) => {
      controlsSticky.classList.toggle('stuck', !entry.isIntersecting);
    },
    {
      root: null,
      threshold: [0],
      rootMargin: `-${getComputedStyle(controlsSticky).top} 0px 0px 0px`,
    }
  );
  observer.observe(controlsStickySentinel);
}
```

Add show/hide calls for legend in the `analyze()` function:

```javascript
function analyze() {
  // ...

  if (!text) {
    hide($('tokenView'));
    hide($('legend'));  // NEW: hide legend when no text
    show($('emptyState'));
    // ...
  } else {
    hide($('emptyState'));
    // ...
    show($('tokenView'));
    show($('legend'));  // NEW: show legend when tokens displayed
  }
}
```

Also update the cached-input branch so the moved legend is restored whenever the
token view is restored:

```javascript
// Skip re-tokenizing if the raw input hasn't changed
if (raw === lastRawInput) {
  show($('tokenView'));
  show($('legend'));  // NEW: legend now lives outside tokenView
  return;
}
```

Also ensure legend is hidden on init (in `initWithRetry` success path):

```javascript
setStatus(null);
show($('emptyState'));
hide($('legend'));  // NEW: ensure legend hidden on init
```

## Z-Index Hierarchy

```text
1000 │ Welcome/Help overlay
 200 │ Panel-word-overlay (expanded morpheme)
 100 │ Panel (word details at bottom)
  10 │ CONTROLS-STICKY ← NEW
   0 │ Scrolling content (token-area, footer, etc.)
```

## Edge Cases

| Case                    | Behavior                                                              |
| ----------------------- | --------------------------------------------------------------------- |
| TokenView hidden        | Legend also hidden via `hidden` class                                 |
| Status box shown/hidden | Independent, works in sticky wrapper                                  |
| Panel at bottom         | `position: fixed`, unaffected by sticky controls                      |
| Header scroll           | Header scrolls away normally; it is not pinned                        |
| Controls stuck          | Thin bottom separator appears via `.stuck` class                      |
| Controls unstuck        | Thin bottom separator removed                                         |
| Top gutter              | Background apron hides scrolling content above stuck controls         |
| Vertical reading mode   | Button remains accessible at top when stuck                           |
| Mobile viewport         | Inner controls wrapper can scroll if controls exceed viewport         |
| Resized textarea        | Mobile max-height prevents textarea from hiding all reading content   |
| No IntersectionObserver | Graceful degradation — controls stick, no visual stuck-state feedback |
